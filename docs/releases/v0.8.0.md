# AgentDir v0.8.0

Fixes two ways evidence could quietly fail to mean anything, adds structured
claims, and puts the test suite under CI.

The minor version moves because `agentdir audit claims` can now report `ok=false`
on text that previously passed. See **Behaviour changes** before upgrading a
pipeline that runs it with `--strict`.

## Fixed

### Worktree checkouts no longer fragment the store

`git rev-parse --show-toplevel` reports the *linked* worktree, so every
`git worktree` checkout resolved to its own `.agentdir`. A repository's evidence
and memory split into one store per branch, and an agent working in a worktree
saw `memory_hits=0` while the main tree's history sat alongside it, unreachable
and unmentioned.

Linked worktrees now resolve to the main working tree's store. Each worktree
keeps its own active session, so parallel agents do not overwrite each other.

A store already present inside a worktree still wins, so nothing recorded there
is orphaned, and `AGENTDIR_WORKTREE_STORE=local` opts out. `agentdir doctor`
warns when a worktree store is separate from the main one and names the command
that joins them for search.

### Context packs were broken on Python 3.11

A header longer than the fold width is written across continuation lines.
Python 3.12 and newer strip the continuation's leading whitespace when the value
is read back; 3.11 does not. `X-AgentDir-Blob-SHA256` is 89 characters with its
name, so it always folds, and on 3.11 every artifact lookup carried a leading
space and never matched — `Context pack manifest artifact is missing` for a blob
sitting right there.

This affected context packs, the doctor's artifact check, and the secret
scanner, on the minimum Python AgentDir declares and ships to PyPI. Header
values are now normalised when parsed.

**A store indexed by an affected 3.11 install keeps the padded values in its
SQLite sidecar.** `agentdir doctor` now warns when it finds them; run
`agentdir index rebuild` to restore them from the envelopes, which were always
correct.

### `audit claims` no longer passes because it understood nothing

Claim detection is keyword-based, so ordinary phrasing ("everything works",
"verified locally", "no regressions") matched no family and returned
`ok=true claims=none` over recorded test failures — which reads as "audited and
clean" when the truth is "never audited".

Failed evidence the text makes no checkable claim about is now `unreviewed` and
not ok. Text that reports the failure ("tests failed") is `acknowledged` and
does not count against the audit, so honest failure reporting is not flagged
like text that hid the failure. Failure vocabulary asserting success ("no test
failures") is treated as a success claim and checked like any other.

### `status` and `doctor` printed everything twice

The recording console had no output sink, so rich wrote each table to stdout as
well as recording it, and the caller printed the exported copy.

## Added

### Structured claims

```bash
agentdir claim test --passed
agentdir claim build --failed --note "linker error in release profile"
agentdir claim list
agentdir audit claims          # compares recorded claims against evidence
```

A recorded claim names its family and outcome outright, so checking it is a
comparison rather than an interpretation of prose:

| Claim | Evidence | Result |
| --- | --- | --- |
| passed | succeeded | `supported` |
| passed | failed | `contradicted` |
| failed | failed | `acknowledged` |
| failed | succeeded | `contradicted` |
| either | none recorded | `unsupported` |
| none recorded | failed | `unreviewed` |

Re-recording a family replaces its earlier claim. `agentdir claim <family>
--retract` withdraws one made in error; claims are append-only events, so
retraction supersedes in the latest-claim view while leaving both in the record.

Recorded claims reach the `agent_handoff` object with no final text supplied.
Prose auditing stays available as `agentdir audit claims --text <path|->`.

### Continuous integration

The suite runs on every push and pull request across Python 3.11, 3.12 and 3.13
plus macOS, alongside checks that the distribution builds, `twine` accepts its
metadata, `package.json` and `pyproject.toml` agree on the version, and the
install scripts parse. Its first run is what surfaced the Python 3.11 bug above.

## Behaviour changes

- **`agentdir audit claims` can now report `ok=false` where it previously
  reported `ok=true`**, and `--strict` exits 1 accordingly. This is the point of
  the fix, but a pipeline that runs it with `--strict` over final text may start
  failing on sessions that have failed evidence the text does not mention. Record
  the outcome with `agentdir claim`, or state the failing check in the text.
- `agentdir audit claims` without `--text` now audits recorded claims instead of
  exiting 2 for a missing argument.
- The active-session pointer moved to
  `state/workspaces/<workspace>/current-session.json`. The unscoped pointer is
  still written, so downgrading to 0.7.x keeps working.
- Commands run inside a linked worktree may now resolve to a different store
  than before. Set `AGENTDIR_WORKTREE_STORE=local` to keep the previous
  behaviour.

## Upgrading

```bash
agentdir update
```

If the repository has worktrees adopted before this release, `agentdir doctor`
reports which stores are split and how to join them. On Python 3.11, run
`agentdir index rebuild` once if doctor reports folded header values.
